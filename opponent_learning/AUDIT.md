## 🔴 #1: Train/test split в imitation НЕ по эпизоду

**Код** (`05_train_imitation.py`, строки 154–158):
```python
X = df[STATE_COLS].values
X_tr, X_te = train_test_split(X, test_size=0.15, random_state=42)
tr_idx, te_idx = train_test_split(np.arange(len(df)),
                                  test_size=0.15, random_state=42)
```

**Что не так**. `train_test_split` режет случайно по **строкам**, а строки сильно коррелированы внутри эпизода (соседние шаги почти одинаковы). 360,588 строк из 500 эпизодов = ~720 строк/эпизод. При 15% test = ~108 шагов каждого эпизода в test, остальные 612 — в train. Модель **видит почти весь эпизод в train и тестируется на оставшихся подобных шагах того же эпизода**.

**Следствие**. Все метрики `action_*.json` моделей (acc/f1/MAE/R²) систематически завышены. Они не говорят ничего про обобщение на новые партии. Это и есть та "ложь успеха", которая отговаривает от поиска лучшего решения.

**Доказательство**. В соседнем `10_value_function.py:151–158` сделано **правильно**:
```python
def split_by_episode(df_full, val_frac=0.15):
    eids = df_full['episode_id'].unique()
    rng = np.random.default_rng(42)
    rng.shuffle(eids)
    val_eids = set(eids[:int(len(eids) * val_frac)])
    return df_full['episode_id'].isin(val_eids)
```

И value function показывает AUC 0.91 — **честная цифра**. А imitation модели рядом — все с обоснованно подозрительно хорошими метриками на data leak'нутых разбиениях.

**Исправление**. Заменить `train_test_split` на `split_by_episode` в `05_train_imitation.py`. После этого все метрики ухудшатся (на 5–15 пунктов точности) — это будет **настоящая база** для дальнейшей работы.

## 🔴 #2: Value function учит "кто победил", а не "P(win)"

**Код** (`10_value_function.py:73–126`). State features включают:

```python
STATE_FEATURES = [
    ...,
    'phase',                # ← доля времени партии
    'did_act',              # ← действие игрока
    'n_launches',           # ← действие игрока
    'ships_fraction_sent',  # ← действие игрока
    'attack_enemy_ratio',   # ← действие игрока
    'attack_neutral_ratio', # ← действие игрока
    'reinforce_ratio',      # ← действие игрока
    'avg_overkill',         # ← действие игрока
    'avg_target_dist_frac', # ← действие игрока
    'multi_launch',         # ← действие игрока
]
```

**Что не так — две проблемы в одной**:

**(а) Endogeneity action features**. `attack_enemy_ratio` — это **то, что игрок сделал**. У победителей и проигравших разные действия по разным причинам. Включать действие как фичу для предсказания исхода = предсказывать исход по самому действию = тавтология.

**(б) phase = время — позволяет тривиально доминировать концовкой**. В моих замерах:
```
phase → did_act → reward (per quartile)
q1 (0.00–0.25):  did_act 32%   reward mean -0.39
q4 (0.75–1.00):  did_act 26%   reward mean -0.39
```
Reward константа по фазам в среднем (потому что мы смешали игроков). Но **внутри одного игрока** на q4 победитель уже на ~+1, проигравший на -1. Модель ловит "phase=0.9 + лидер по производству → выигрывает". Это **не value function**, это **classifier "это тот, кто выиграл партию?"**.

**Доказательство — top-15 feature importances** (из `value_function_meta.json`):
```
prod_gap          0.361
own_prod_ratio    0.151
own_planet_ratio  0.116
ship_gap          0.043
```
Все четыре — макро-агрегаты, описывающие **уже накопленное** превосходство. Это **followers** скилла, не **leaders**. Стратегия "максимизируй prod_gap" бессодержательна, потому что prod_gap — результат, а не рычаг.

**Следствие**. AUC 0.91 звучит хорошо, но эта модель НЕ годится для:
- Offline RL critic (она endogenous)
- MCTS prior (тривиально завышенная уверенность по фазе)
- Filtering данных по решённости (она и есть оценка решённости, но без честной calibration)

**Исправление**. Переобучить value function:
1. Только state features, **без** action.
2. **Без** `phase` (или с phase как stratification axis, не как input).
3. Стратифицировать метрики по `phase` и докладывать AUC/log-loss отдельно для early/mid/late.

Это даст реалистичную оценку (вероятно AUC 0.75 в среднем, 0.55 в early, 0.95 в late) — но это уже **полезная** функция.

## 🔴 #3: Кластеризация стилей кодирует исход

**Доказательство — winrate per cluster**:
```
cluster   n     winrate
0        82    0.427
1       570    0.012   ← "balanced", практически никогда не побеждают
2       227    0.013   ← "turtle", практически никогда не побеждают  
3       360    0.575
4       299    0.829   ← "hoarder", побеждают в 83% случаев
```

**Что не так**. Кластеры 1 и 2 имеют winrate 1.2% и 1.3% — это **не "стиль игры"**, это **"проигравшие"**. Аналогично cluster 4 — это, возможно, не специфический агрессивный стиль, а просто **категория, куда падают победители**.

В 4-player FFA партиях 3 из 4 игроков проигрывают (rewards: `[1, -1, -1, -1]`), что искусственно перегружает классы "балансированный" и "черепаха" проигравшими.

**Следствие**. Cluster ID — это **прокси для outcome** под маской "стиля". Когда `05_train_imitation.py` обучает cluster_likelihood модель — она фактически предсказывает исход через переменную, которая закодировала исход. Цепочка `gradient_field → cluster_likelihood → bayes prior` использует эту скрытую утечку.

**Исправление**. 
1. Кластеризовать **только победителей** (cluster — "стиль успешного игрока").
2. Или: убрать reward/outcome из фич кластеризации, оставить только action statistics.
3. Сравнить с null'ом: shuffle кластеры случайно, посмотреть какие свойства сохраняются.

## 🔴 #4: Asymmetric reward dataset — смешанные 1v1 и FFA

**Доказательство**:
```
reward distribution: -1.0 → 249,837 (69%);  +1.0 → 110,751 (31%)
```

В чистом 1v1 это должно быть ~50/50. 31/69 говорит, что в датасете есть значительная доля 4-player FFA, где 3 из 4 проигрывают.

**В моём smoke-тесте я нашёл и 1v1 (n_players=2) и FFA (n_players=4) эпизоды** — это смешанный датасет. Существующий pipeline не различает их.

**Следствие**. Все модели обучены на смешанном датасете без `n_players` как стратификации. Стратегия в 1v1 и в FFA принципиально разные (в FFA важна кулуарная координация против лидера, временный ненападение и т.д.). Smoke-тест показал даже совпадение симулятора с реальностью разное: 96% на 1v1 против 92% на FFA.

**Исправление**.
1. В каждой записи добавить `n_players`.
2. Обучать отдельно (или conditional на n_players) модели для 1v1 и FFA.
3. Подавляющую часть будущего анализа делать на 1v1 (там проще все проверки и интерпретации).

## 🟠 #5: Gradient field в action space, не в map space

**Код** (`07_gradient_field.py:43–54`):
```python
DELTA_DIMS = [
    'd_neutral_grab',    # экспансия в нейтралов
    'd_enemy_press',     # давление на врага
    'd_reinforce',       # оборонительная консолидация
    'd_commitment',      # масштаб вложений
    'd_efficiency',      # точность
    'd_reach',           # дальность атак
    'd_prod_hunger',     # ценность ресурсов
    'd_threat_resp',     # ответ на угрозу
    'd_exp_opportunity', # доступность нейтралов
    'd_position',        # позиция (winning?)
]
```

**Что не так**. Эти 10 измерений — **аспекты распределения собственных действий игрока** (mix атак, расточительности, дальности). Это и есть "локальные паттерны" о которых ты говорил.

Чего нет: **геометрии карты**. Контроль территорий, длина фронта, кривизна, race-pair матрицы, reachability volumes — ничто из этого не входит в "gradient field". Поэтому "gradient" здесь — это не градиент **рельефа влияния** игроков в R²-пространстве карты, а просто **направление в action distribution space**.

**Следствие**. Никакой "глобальной геометрии конфликта" модель не видит. Она видит только "что чаще делал" → не может уловить пространственную инженерию перехода (окружение, отсечение анклавов, удержание ключевых артерий).

**Исправление**. Это и есть основной enhancement в нашем плане: построить **поле контроля над R²** (Voronoi-weighted / time-to-reach / max-flow) и **топологические инварианты** (длина фронта, число компонент, кривизна).

## 🟠 #6: Силуэты launch archetypes 0.13–0.15

**Доказательство** (из `launch_archetypes.json`):
```
neutral:    k=5,  silhouette=0.147
enemy:      k=6,  silhouette=0.134
reinforce:  k=4,  silhouette=0.526
```

**Что не так**. Силуэты `< 0.25` означают **слабо отделимые кластеры**. Для атак на нейтралов и врага кластеры почти "слиплись" в одно облако. Только подкрепления имеют чёткую структуру (0.53).

**Следствие**. "Архетипы" атак — это произвольная пятиугольная нарезка континуального распределения. Когда `07_gradient_field` считает средний gradient на каждом архетипе — это градиенты **искусственных** групп, не настоящих стратегических классов.

**Исправление**. 
1. Сначала выяснить, **сколько на самом деле** различимых архетипов есть (через gap statistic, BIC у GMM, или прицельно сравнить с null'ом — кластеризовать перетасованные данные и посмотреть силуэты).
2. Возможно реальных архетипов нет — тогда лучше моделировать пространство непрерывно (без кластеров), как смесь Гауссиан или нейронную модель.

## 🟠 #7-8: Отсутствует triviality scoring и null models

**Что не так**. Нигде в pipeline нет:
- Разметки трудности состояний (где разные сильные игроки соглашаются vs расходятся; где baselines правы vs ошибаются)
- Сравнения метрик моделей с тривиальными бейзлайнами (`nearest_weakest`, существующий heuristic agent)
- Стратификации метрик по трудности
- Null моделей при заявлениях о структурных находках

**Следствие**. Если модель показывает accuracy 80%, и `nearest_weakest` baseline тоже даёт 75% — это **5 пунктов lift**, а не "модель работает на 80%". Без этой стратификации легко считать что pipeline работает, когда он просто воспроизводит тривиальную статистику.

**Это центральная методологическая дыра**, которую наш план закрывает явно в Phase 0.

**Исправление**. Реализовать `triviality_score` для каждого состояния и пересчитать ВСЕ существующие метрики моделей условно на квартилях трудности. Это может полностью изменить картину "что работает".

## Главный вывод

Pipeline **технически работает**, но методологически **самообманывается** в нескольких ключевых местах:

1. **Imitation models** оценены на leak'нутом split — реальное качество значительно ниже.
2. **Value function** учится сильно через action features и phase — это не value, а winner-classifier.
3. **Кластеры** кодируют outcome — а потом используются как "стиль оппонента" в байесовской модели → циркулярность.
4. **Gradient field** в action space — локальные паттерны, **именно то, что ты хотел заменить** глобальным взглядом на рельеф.

**Поэтому ветка казалась тупиковой**: метрики обманчиво хорошие, а реальной силы агент не набирает. Если переобучить value/imitation честно — метрики упадут, но **появится истинная база**, на которой структурные дополнения (map-space field, фазовый переход, leverage) дадут видимый выигрыш.

## Рекомендуемый первый шаг

Один скрипт-фикс, который перенесёт нас в точку с честной базой:

1. Добавить `n_players` в `02b_extract_steps.py` (быстро).
2. Переписать `05_train_imitation.py` с `split_by_episode`.
3. Переписать `10_value_function.py` без action features и без `phase`, со стратификацией метрик по фазе.
4. Запустить заново — получить **честную базу**.

После этого все остальные ноёшние Фазы плана будут опираться на реальные числа, а не на завышенные. Это 1–2 дня работы и фундаментально меняет картину.

После этого можно решать, где копать дальше — phase transition, map-space field, counterfactual через choice_sets, или что-то ещё.

# Поправки после прогона value_v2

Когда я писал аудит, я делал предположения о размере эффектов. После реального переобучения часть из них оказались неверными. Этот раздел — честная коррекция.

## Поправка к #2 (Value function как winner-classifier) — **смягчить**

**Что я писал**: убрав action features и `phase`, value AUC значительно упадёт (предполагал AUC 0.75–0.85), потому что v1 учился через leaked features.

**Что показал v2**: AUC v1=0.911, AUC v2=0.906 — разница **0.005**.

Action features НЕ давали большого leak'а. Они шумные и слабо коррелированы. Сам `phase` тоже большой роли не сыграл — его место заняли макро-фичи, которые сами по себе сильно растут к концу партии. Это значит:

- Endogeneity была реальной, но эффект на агрегатном AUC мал
- **Главная "endogeneity" — это сами макро-ratio'ы**: они растут к концу партии за счёт компаундированного производства и являются `followers` исхода. И от этого никуда не уйти, эти ratio объективно описывают позицию

Жёсткость пункта #2: ~~🔴 Критично~~ → 🟡 Заметно (концептуально неверная модель, но численно эффект 0.005 AUC).

## Поправка к #5 (Gradient field в action space) — **усилить**

**Что я писал**: gradient field в action space — это локальные паттерны, а нам нужны пространственные структуры в map space.

**Что показал v2**: добавление 29 структурных скалярных фич поверх 5 макро-ratio'ов даёт lift **+0.0009 AUC** (фактически ноль). `fleet_balance`, `own_under_threat_count`, `proj_*`, `closest_threat_dist`, `std_own_ships` — всё бесполезно.

То есть проблема ещё глубже, чем я предполагал. Не только gradient field в action space был локальным — **скалярные структурные представления вообще не несут информации поверх простого баланса ресурсов**. Любые "agregaty + counts" работают плохо.

Это резко повышает важность настоящей **пространственной** структуры (поле в R², топология, race-pair матрицы) — потому что только она ещё не пробовалась. Но и снижает уверенность: возможно, **никакая** дополнительная фича не даст лифта, потому что баланс ресурсов уже всё объясняет.

Жёсткость #5: 🟠 Значительно → **🔴 Критично + open question** (стоит ли вообще тратить силы на структурные фичи).

## Новое наблюдение #N: Игра решается плавной S-кривой (НЕ резкий фазовый переход)

Это не было в исходном аудите. Стратификация AUC по phase:

```
phase 0.00–0.20:  AUC ≈ 0.60 → 0.75 (зона интереса — модель не уверена)
phase 0.20–0.55:  AUC ≈ 0.75 → 0.93 (плавный рост)
phase 0.55–1.00:  AUC > 0.94 (endgame, всё уже решено)
```

Это **гладкая S-кривая**, не резкий скачок. Максимальный градиент между соседними 20-бинами +0.05 AUC. variance V across replays **монотонно** растёт (нет peak'а) — нет critical slowing down.

**Концепция "фазового перехода в физическом смысле" эмпирически не подтверждена.** Это просто плавное затухание неопределённости. Это закрывает Phase 4 нашего исходного плана как самостоятельное направление.

**Что осталось значимым практически**:
- В q1 (phase < 0.2) AUC < 0.75 — это **зона где скилл реально различает игроков**
- В phase > 0.55 AUC > 0.94 — это **endgame шум для BC обучения**, нужен filtering
- Типичный момент решения партии — phase ≈ 0.40 ± 0.20 (унимодальное распределение)

## Откатанные наблюдения после 04_diagnostics

При первом анализе я выдал два промежуточных вывода — оба оказались артефактами:

**Откатано: "Стартовая позиция несёт сигнал"** — `V(winners) ≠ V(losers)` в phase=0 был артефактом смешения 1v1 (winrate 0.5) и FFA (winrate 0.25). Стратифицированно по `n_players`: gap = -0.001 в обеих стратах, p > 0.3. Стартовые позиции **симметричны** (median diff в raw features = 0.0000).

**Откатано: "Два архетипа партий (early/late decisive)"** — бимодальность `argmax |dV/dt|` оказалась boundary effect свёртки `mode='same'`. На raw данных или с обрезкой 10% краёв распределение **унимодальное** с центром около 0.40.

Это методологическая ошибка с моей стороны — выводы делались до проверки на null/edge-effects. В дальнейшем все новые наблюдения сначала через diagnostics, потом интерпретация.
