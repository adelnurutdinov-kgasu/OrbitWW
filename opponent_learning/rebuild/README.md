# rebuild/ — переделанный pipeline по результатам аудита

Эта папка существует чтобы **не путать качественное с непроверенным**. Принцип:

- `opponent_learning/scripts/` — исходный pipeline. **Не трогаем**. Это историческая база.
- `opponent_learning/rebuild/` — здесь живёт всё, что **прошло аудит и было переделано**. Если что-то лежит тут — значит у нас есть доказательства, что методология чистая, что метрики честные, и что находки не артефакт leakage'а.

Каждый скрипт в `rebuild/scripts/` соответствует одной из проблем, найденных в `../AUDIT.md`. В заголовке скрипта явно написано: что было не так в оригинале, что изменилось, что ожидается на выходе.

## Структура

```
rebuild/
├── README.md                  ← этот файл
├── scripts/                   ← переделанные скрипты
│   ├── 01_episode_metadata.py    – augmentation: n_players, outcome, имена
│   ├── 02_value_function_v2.py   – value без endogenous фич
│   └── (далее по аудиту)
├── data/                      ← выходные данные (episodes_meta.csv и т.д.)
├── models/                    ← переобученные модели (value_v2.json и т.д.)
└── reports/                   ← отчёты с метриками и сравнениями
```

## Как запускать

Лёгкие скрипты (метаданные, оценка) — я запущу прямо в сессии.

Тяжёлые скрипты (обучение моделей на 360K строк, парсинг 2.6 GB) — лучше запускать локально:
```bash
cd /Users/adel/Documents/GitHub/OrbitWW
python3 opponent_learning/rebuild/scripts/<имя_скрипта>.py
```

Каждый скрипт в начале файла говорит: лёгкий он или тяжёлый, и сколько примерно времени занимает.

## Принцип отчётности

Каждый запущенный скрипт пишет:
- Модели → `models/<имя>.json`
- Метрики → `reports/<имя>_metrics.json`  
- Сравнения с оригиналом → `reports/<имя>_vs_v1.md` (где применимо)

После любого переобучения смотрим `reports/` — там короткий отчёт что изменилось и какие выводы.
